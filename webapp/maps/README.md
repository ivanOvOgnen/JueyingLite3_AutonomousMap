# Hosted map files

The first manually guided scan is saved here as `lite3_room.pgm` and `lite3_room.yaml`. The web app's hosted-map fields default to these same-origin files.

The follow-up scan captured on 2026-09-30 is preserved separately as `lite3_room_scan_20260930.pgm` and `lite3_room_scan_20260930.yaml`. To preview it in the hosted-map section, enter `/maps/lite3_room_scan_20260930.pgm` and `/maps/lite3_room_scan_20260930.yaml`. The map is sparse and distorted, so it is for review only and must not be used for click-to-go navigation.

Do not copy `config/mapping.yaml` from the ROS package: it configures SLAM and is not saved map metadata. New maps should be copied here with their matching map-server YAML metadata.

Each checked-in map pair has a matching `.audit.md` baseline generated by `scripts/map_quality_report.py`. The report counts cells with the YAML thresholds and checks free-space connectivity as a comparison aid; review the rendered map and scan behavior as well.

## Saved-map sidecar and optional 3D evidence

New maps saved through the project API also receive `<map>.lite3-map.json`. This
versioned sidecar records the matching PGM/YAML coordinate convention and makes
the absence of a registered cloud explicit. The original PGM/YAML remains the
authoritative Nav2 map, so older map pairs work unchanged.

A saved room cloud, when one has passed timestamp and map-frame registration
checks, may be stored separately as a binary or ASCII PLY in ROS `map`
coordinates with metres as units. The Room Mapper no longer has a saved-PLY
viewer. Do not attach the raw RealSense cloud or the live stitched-preview
buffer: the current camera point-cloud timestamp defect makes either
unsuitable as persistent evidence.
